What Wallie_911_Pro is — and what it is not

A short, honest explanation of the matric rescue cockpit built for Wallie van Zyl: the features, the learning science behind it, how it is put together, and what success actually depends on if he follows the plan through to exams on 12 October 2026.

Not an LMS Not motivation theatre Exam rescue system Live for Wallie now

1. In one sentence

Wallie_911_Pro is a focused Afrikaans study cockpit that turns each afternoon into supervised, exam-style practice — with a camera lock when he looks away, picture-first lessons, a fault bank that becomes tomorrow’s plan, and a live parent console so Pa can see whether a session is real.

Try it here (browser only — no install): pamoja-academy.github.io/Wallie_911_Pro

2. Why it exists

Prelims showed a clear pattern: avoidance, “I read it” without production, and red-zone subjects far below a safe pass. Traditional homework and “study harder” did not close that gap. The design brief (Sept 2026) chose a rescue cockpit, not another content library:

  • Break avoidance with hard session observation (camera + tab focus).
  • Replace rereading with closed-book attempt → memo → fault log.
  • Prioritise the weakest subjects first, every day until 12 Oct.
  • Give Pa remote eyes when he cannot sit in the outbuilding.
Targets written into the app: every subject ≥ 60%; Mathematical Literacy ≥ 80%; English ≥ 70%; ≥ 90% of planned daily blocks completed under observer mode.

3. Exact feature set (what the principal would see)

For Wallie (laptop)

  • Mission board — daily plan (about 6–7 hours), countdown to 12 Oct 09:00, Springbok “#15” narrative so the clock feels like a match, not a lecture.
  • Visual lessons (Lesse) — one concept per screen: study the picture → close the book → write what you remember → open the memo. Misses go into the fault bank.
  • Hard observer session — camera on; leaving the tab or another program counts as a warning; 3 warnings lock the session until Pa’s PIN (9110). Opening the lesson or an in-app memo does not count as looking away.
  • Subjects & low-hanging fruit — each subject card shows prelim mark, target, and a short “easy marks” checklist (rubric language, definitions, timed drills).
  • Fault bank (Foutbank) — every wrong answer becomes a retest item. That list is the real syllabus for the next days.
  • Paper upload — hybrid: upload past paper + memo PDFs; metadata stays in the browser.
  • Surveys & improve loop — Wallie’s self-report plus Pa’s check; where they disagree, Pa’s eyes win.
  • Export log — one-tap download/share of the full camp log to Pa.

For Pa (phone)

  • Live console (pa-afstand.html) — password-gated. During a hard session: subject, time left, warnings, lock state, heartbeat age, and a small camera still about every 45 seconds. No continuous cloud video.
  • Push alerts (ntfy topic) for session start, lock, unlock, end — not a flood of heartbeats.
  • Session history that survives longer than a 12-hour push cache.

4. Why this approach can work (the learning science)

The core methods are the two strategies Dunlosky and colleagues (2013) rated high utility for learning:

  1. Practice testing with feedback — closed book → memo → mark faults → retest.
  2. Spaced repetition — the same weak point returns over days, not one marathon cram.

Rescued for a short runway (~days until 12 Oct), that becomes:

  • Low-hanging fruit first — rubric language, definitions, short questions before deep essays.
  • Exam behaviour every block — timing, instruction words, “read the question”.
  • No “I read it” illusion — observer + blank-page production required.
  • Fault log = syllabus — tomorrow prioritises open faults.
Mission→ Hard session→ Picture / paper→ Closed book→ Memo→ Fault bank→ Pa sees it

5. How it is put together (architecture, plain language)

What it runs on Static HTML, CSS and JavaScript hosted on GitHub Pages. Wallie opens a normal browser link. No app store, no Node install required for daily use.
Where data lives Study progress and logs start on the laptop (localStorage). Live session status and stills go to a small, isolated cloud schema so Pa’s phone can watch. Still images auto-expire after a few days. Full video is never uploaded.
Language & UX UI in Afrikaans for Wallie. Matchday metaphor (Mission, jersey #15, kickoff) to make the calendar visceral without turning it into a game that distracts from work.
Quality checks Automated smoke and proctor tests run on the code (soft-lock rules, durable session outbox). Browser walkthroughs checked picture lessons and session behaviour before merge.

Privacy posture (by design): Pa gets status, warnings, and occasional stills during a live hard session — not a continuous cloud CCTV archive. Wallie consents on-device (consent bumped when stills began leaving the laptop).

6. Assurances — what anyone can honestly claim

Nobody can guarantee a matric mark from software alone. What this system can honestly offer is a disciplined path whose success conditions are visible and checkable.

If Wallie completes every planned session as designed, you get:

  1. Hours of supervised, timed, closed-book production instead of unsupervised “studying”.
  2. A growing fault bank that forces rework of real weaknesses.
  3. Daily pressure on the three red subjects that currently decide the pass.
  4. Pa’s ability to verify — live — that a session happened, in which subject, with how many warnings.
  5. A written success bar the family already agreed: 60% / 80% Math Lit / 70% English, and ≥90% of planned blocks done under observer mode.

What still has to be true (parent and school eyes)

  • He actually starts the blocks and accepts the camera consent.
  • Pa uses the live console or spot-checks — “his word” is not enough when production looks busy but empty.
  • Past papers and memos get used (hybrid upload), not only the built-in picture lessons.
  • Sleep, nutrition, and exam-day logistics remain adult responsibilities — the app does not replace parenting or teaching.
Honest limit: following the flow raises the probability of hitting the rescue targets because it implements high-utility study methods under observation. It does not manufacture understanding without effort, and it will not fix a day he simply does not open it.
What “success if they follow the flow” means here: complete the Mission plan each day under hard sessions; do picture → closed book → memo; clear fault-bank items; keep Pa’s console open when you cannot sit with him. That is the contract. Marks follow effort against that contract — not the jersey story.
